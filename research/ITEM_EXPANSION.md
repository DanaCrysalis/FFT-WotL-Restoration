# War of the Lions items in Ivalice Chronicles

How the WotL Characters mod gives WotL's 40 own items (ids 0x100–0x139) a place in IC, which has room for 261 items. Found 2026-09-25 on the Steam build of 2026-09-17 (no Denuvo; disk bytes are memory bytes). RVAs throughout.

Code: `ItemExpansion.cs` (runtime), `ItemSites.g.cs` (generated by `tools/item_sites.py`), `ItemData.g.cs` (generated by `tools/wotl_items.py`), text rows and icons in `tools/build_data.py` (`WOTL_ITEMS`).

Map used alongside our own disassembly: prawl's FFTLivingWeapons (weapons only, ids 261+; its repo has no licence, so only its notes were read). Its 1.5.2 addresses match this build.

## The short version

IC's item code is WotL's own. It has the same 14-entry range table, the same data-type tables and the same getters, but its secondary data covers only IC's five items: 0x100 Materia Blade+, 0x101–0x103 the Akademy bonus items, 0x104 Ring of Aptitude.

WotL's layout is:

| Range | Items |
|---|---|
| 0x100–0x11F | Weapons |
| 0x120–0x123 | Shields |
| 0x124–0x12B | Helmets |
| 0x12C–0x133 | Body armor |
| 0x134–0x13B | Accessories |

IC code still special-cases WotL's own ids. For example, the can-equip check reserves the Onion gear (0x106, 0x120, 0x125, 0x12D, 0x136) for jobs 0xA1/0xA4. So WotL items keep their WotL ids, except the five Fell Swords (0x100–0x104, taken by IC's items), which move to 0x116–0x11A.

The hard limits are not the tables but the arrays and bounds sized for 0x105 ids, and the save file, which has no room for more. The mod:

1. **Moves the per-item arrays to a page near the executable**, re-pointing all 63 instructions that address them:
   - the bag counts (0x11A7C00);
   - the owned mirror (0x3C52740);
   - the equipment bonus table (0x80FEA0, 0x55 rows of 0x1A bytes);
   - the equip picker's all-items chart (0x1874726).
2. **Moves the nine menu order charts** by rewriting the 14 pointer slots every live reader uses. Only save/load/init copies name the vanilla blocks.
3. **Widens 28 bounds** that must accept the new ids, and leaves the others alone on purpose (below).
4. **Hooks the item getters** so that ids 0x105+ are answered from the page. Everything below 0x105 runs the game's own code.
5. **Keeps the save format.** The new items' counts ride in the event variable block's unused tail. Charts are projected back onto their vanilla save fields. A save therefore loads without the mod; the new items then simply vanish.

Every patched byte is checked first. A game update disarms the whole expansion (logged per site); it never half-arms. The birthday reward then falls back to a Septième Sens.

## Getters (all hooked; 0x2B8BCC–0x2B8EF0 is the only code that reads the tables)

| RVA | Function | Vanilla data |
|---|---|---|
| 0x2B8BCC | range index of an id (−1 invalid). Hard-coded: ≤ 0xFD or 0x100–0x104 | ranges u16[14] at 0x6804E0 |
| 0x2B8C0C | first id of an id's data type (only the five sub-getters call it) | types int[13] 0x67FB78, type→range int[10] 0x67FB38 |
| 0x2B8C44 | 12-byte common record | < 0x100: 0x80EA90; else id×12 + 0x67F910 |
| 0x2B8C74 / CD4 / D3C / DA0 / E04 | weapon 8 B / shield 2 / armor 2 / accessory 2 / chemist 3 | 0x80F690 / 0x80FA90 / 0x80FAB0 / 0x80FB30 / 0x80FB70; secondary 0x680500 / 0x672764 / 0x6732FC / 0x673674 / 0x67277C |
| 0x2B8E60 | weapon/shield sprite pair | 0x785CF0 + id×2; secondary 0x672B54 + id×2 |
| 0x2B8EBC | is-valid (same hard-coded 0x104) | – |
| 0x2B8EE8 | same category (range index ±7) | calls 0x2B8BCC |

Range index mod 7 is the category: 0 weapon, 2 shield, 3 helmet, 4 body, 5 accessory, 6 chemist. The data types are 0–4 for primary and 5–9 for secondary. The category getter 0x2890C0 and the can-equip check 0x2886D0 go through these, so they follow the hooks automatically.

## Where the new items' data comes from (WotL BOOT.BIN, vaddr = offset + 0x8803FAC)

| Data | WotL address |
|---|---|
| Common records | 0x8A5ADAC |
| Weapons | 0x8A5B07C |
| Shields | 0x8A5B17C |
| Armor | 0x8A5B184 |
| Accessories | 0x8A5B1A4 |
| Bonus rows 0x50–0x64 (0x19 bytes) | 0x8A5B1B8 |
| Sprite pairs | 0x8A5B3C8 |

WotL's bonus rows 0x50–0x64 are IC's bonus items' rows 0x50–0x54, so they become IC 0x55–0x69; IC's rows carry a 26th flag byte (0).

Item types 0x23 (Fell Sword) and 0x24 (lip rouge) still exist in IC's code (user's reading), but not in its UI category list (0–34). The Tynar Rouge becomes a Perfume (0x1F), a user decision, and Fell Swords keep 0x23.

Record byte 4 is the index in the item's vanilla sub-table. The getters ignore it, and IC's bonus items copy a vanilla item's value. New items take a donor's value: the strongest vanilla item of the same type, or Septième Sens's for the Tynar Rouge.

## Saving

The save work struct (0x9CDC bytes) packs PartyItem[0x105], ShopItem[0x105], FindItem[0x80], the event block (0x400) and the menu charts with no slack. Findings:

- **Event block.** The event variable function 0x2EC298 maps vars 0–0x7F to u32s, 0x80–0x35F to bit flags from +0x200, and 0x360–0x3FF to bytes from +0x25C, so its reach ends at +0x2FC. The block is copied whole by:
  - the serializer 0x218F78;
  - load 0x21B0E8;
  - battle suspend 0x2CDBC4 and resume 0x2CE7A8.
  No code references its tail, and the tail is zero in every save checked. The mod keeps `"WC", 1, 0` and one count per id from 0x105 at +0x2FC. Mid-battle saves are covered too, so no sidecar is needed.
- **Charts.** The save copies (0x2194BC and so on) and loads (0x21B4BD and so on) name the vanilla blocks directly. The mod's sync thread, every 50 ms and at the serializer's entry, works both ways:
  - a vanilla block that changed (a load, new game, battle restore or tool) is adopted by the page;
  - a page that changed is projected back with vanilla ids only (≤ capacity − 1, then the 0x00FF marker).
  A mod-less load therefore never meets a new id. After a load the game's own chart housekeeper re-inserts the owned new items.
- **Vanilla bag.** It is kept equal to the page both ways, for cheat tables and tools.

## Bounds

**Widened** (see `BOUNDS` in `tools/item_sites.py` for the exact bytes):
- the bag accessor 0x2847F8 and the count getter 0x287564;
- menu counts 0x15415B, "has item" 0x100F82 and bag add 0x101070;
- return to bag 0x23D592 and the clamp-to-99 loop 0x2846E8;
- the menu list builder 0x288B94 and its twin 0x39711F, and the sell list 0x289072;
- chart walks 0x285E2C, 0x2862F6, 0x39678E and 0x285EE4, and the three chart housekeepers 0x285F80, 0x286070 and 0x39684C (their `lea r14d, [r15+6]` bounds, invisible to imm32 scans);
- the all-items maintainer 0x286160 and the status screen copy 0x2BDA4D;
- equipment bonuses 0x277A99 and the five bonus-row bounds `cmp …, 0x55` (0xFA7E2, 0x277AA8, 0x286D81, 0x29F726, 0x396A6F);
- the owned-mirror rebuild 0x396174, which copies 8 × 0x80 + 5 bytes instead of 2 × 0x80 + 5. Its stride is count + 0x7E, so that byte changes too.

**Left alone on purpose.** At these sites a new id reads as "no item", which is safe:
- **Fixed buffers indexed by id.**
  - 0x2D6688, the "carrying 100 of something" check: a 0x110-byte stack buffer. Its two IsValidItem calls go to a stub that refuses ids ≥ 0x105.
  - 0x2C8152, 0x2C62A0 and 0x2C8063: auto-sell at 100 into a u32-per-id stack array.
  - 0x284553, the inventory reset: it zeroes 0–0x104 only, so the new counts survive it.
  - 0x11A7810, a u16-per-item "new in stock" array ending at the poach table: its users check ≤ 0x104 themselves.
- **Battle specials**: steal/break 0x306xxx, 0x30BF9B, 0x309951, 0x3019B5, 0x2FA287/427, 0x32F…, 0x33A… and 0x399D…. New items can't be stolen or broken yet.
- The hand-slot checks ("right hand ≥ 0x105 → left hand") were widened in 1.17.0 for Ras Algethi, the first new weapon: 0x226FDD and its copies (0x2C4EB5, 0x2DE6FD, 0x2FE434, 0x33B5B9, 0x37863E), 0x27F000, 0x2822A1, 0x284C08, 0x3602F3, 0x396368, 0x3059BE, 0x309EF6, 0x28024D and 0x1ED958/97F.

## Balthier's gear

WotL didn't put its items in the ENTD, where items are bytes; ENTD 514/528 carry his vanilla gear in WotL as well. Instead, the unit setup loop (WotL 0x88BAE4, IC 0x27176B, the same code) checks:
- unit byte 0 == 0xA2 (Balthier);
- event variable 0x27 (the event being played) == 0x206 (518, his battle's stub).

It then copies the 7-word table at IC 0x714460 (`0, 0x12F, 0, 0x107, 0, 0, 0`) over the unit's equipment from +0x1A, skipping zeros. IC ships the code and the table, so enabling the two items is all it takes.

## Not yet (weapons and shields)

- Menu list caps: the list builder's 0x91 entries and the insert bound 0x92 at 0x288CC3/0x28631A. The two stack-buffer callers hold 152 words, so 140 vanilla hand kinds plus 24 new ones need a buffer swap (prawl's approach).
- The weapon swing art and damage paths.
- Shops: the buy list stops at id 255 and reads the town-flags table 0x67F890.
- Enemies: the ENTD stores item ids as one byte.
- Menu sort: 0x285DF0 slots rows by nxd SortOrder, which must be unique per category.

## Text rows

`Item-en/fr/de/ja` use a base row id (Nex layout `use_base_row_id|true`): the game finds a row by its position from the first key, so the rows after vanilla's 260 must be contiguous. `build_data.py` ships 261–0x13B: the enabled items' rows, and blank ones like vanilla's 254 for the rest. 1.16.0 shipped row 312 alone; it sat at position 261, and the item showed no name, description or icon.

## Checklist for adding an item

1. Add it to `Enabled` in `ItemExpansion.cs`.
2. Add a `WOTL_ITEMS` row in `tools/build_data.py` (text, category, unique SortOrder), which also installs its staged icon.
3. Give it a way to be obtained.

## Status (1.18.0)

All 40 items are enabled, each with a text row, an icon and a menu category. The Fell Swords use a new UIItemCategory row 35.

Only three can be obtained:
- the Tynar Rouge, from Agrias's Birthday;
- Ras Algethi and Mirage Vest, on Balthier.

WotL's other items came from its multiplayer modes, so they have no source in IC yet.

IC's JobData still has WotL's Dark Knight (0xA0, 0xAF) and Onion Knight (0xA1/0xA4), with Fell Swords (0x23) in their equipment masks. They are unnamed and unreachable, so no current unit can equip Fell Swords or the Onion gear.
