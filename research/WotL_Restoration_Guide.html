A walkthrough of every part of the WotL Restoration mod, written so you can repeat or extend the work from the game files alone. It covers the War of the Lions scenes, battles, rumors, characters, items, maps and battle minimaps the mod puts back into Ivalice Chronicles.

What the mod does

Ivalice Chronicles (IC) is built on the PSX game, but its data still carries a lot of War of the Lions (WotL). The exe has WotL's event setup records 512–599, the ENTD casts for them, WotL's item code and most of its item tables. What it lacks is everything that makes those records play: scripts, text, triggers, battle rules, some art, and the table rows the enhanced UI needs.

The mod fills those gaps. In outline:

  • Every WotL-only story scene (events 512–581): Balthier, Luso, Agrias's Birthday, Zeirchele Falls, Argath at Limberry, Beowulf and Reis, and the rest (see the catalog). Each one fires under WotL's own conditions.
  • Four restored tavern rumors, which unlock Balthier, Beowulf and Reis, and the Deserters battle.
  • WotL's characters as proper units: names, jobs, job commands, sprite shapes and portraits for Balthier, Luso, Argath the Deathknight, Aliste, Bremondt and the Dark Dragon.
  • All 40 WotL items in the item tables, with WotL's own ids, names, icons and effects.
  • WotL's map 127 (Limberry Castle Inner Court), a battle surface for a cutscene-only map, and a 4-stage version of IC's Limberry battle minimap.

How the mod is put together

The mod has two halves. The data half is plain files under FFTIVC/, which the modloader serves in place of the game's own. The code half is a small Reloaded-II DLL that patches the exe in memory at startup. It only does what data can't.

Every exe location is found by a byte signature, and the bytes are checked before they're patched. If a game update moves or changes something, that feature logs a warning and stays off, rather than writing into the wrong place.

Rules that apply everywhere

Editing nxd tables

Convert a folder of .nxd files to SQLite with FF16Tools.CLI nxd-to-sqlite -i in -o db.sqlite -g fft, edit the rows, and convert back with sqlite-to-nxd -i db.sqlite -o out -g fft -t Table1 Table2 …. Ship only the tables you changed. The modloader compares each shipped table with vanilla and merges the added or changed rows. Its log says so ("Processing 2 added rows for nex table 'entryno'"), so two mods can add rows to the same table.

The exported tables have no primary key, so delete a row before re-inserting it rather than using INSERT OR REPLACE.

Base-row-id tables must stay contiguous

A single-keyed table whose header sets use_base_row_id is read as a plain array: the row for key k is at position k − first key. Adding key 514 after a table that ends at 511 puts it at position 512, and the game reads past the end. It crashed on Balthier's EntryNo row for exactly this reason.

KindTables this mod touchesAdding a row
Base row id (array)EntryNo, CharShape, Item-*, UIItemCategory-*, Gossip-*, EventIdFill every key up to yours, with blank rows if needed
Sparse or hashedCaption, PlaceName-*, RefinedBgMeshNode, Speaker-*, ScenarioId, ScionFiles, ContinuousSortieConfirmAny free key works

The lookup for single-keyed tables is at RVA 0x3D3AE8. It has three modes: array (base row id), a sparse pointer array over min..max, or a hash.

Which files can be added

  • Path-based files (bg/…, ui/…, nxd/…, script/…, system/…) can be new. The mod adds a new scenario text file, map 127's mesh and a texture folder.
  • fftpack files are addressed by index. The modloader can only replace an index that already exists (its list is FileLists/fftpack.txt), so you can't add classic map data, new ENTD files or new sprite files.

Finding things in the exe

The Steam build has no Denuvo, so disk bytes are memory bytes: an RVA is file offset + the section delta. Always patch through a signature and check the old bytes first.

Reading War of the Lions' data

Everything comes from two files on the PSP ISO: PSP_GAME/SYSDIR/BOOT.BIN (an unencrypted ELF) and PSP_GAME/USRDIR/fftpack.bin.

fftpack.bin

The header is a u32 file count (3968), a u32 0x10, then count + 1 u32 byte offsets from the start of the pack. File n spans offset[n] to offset[n+1].

FileContents
21TEST.EVT, the event archive: 0x2800-byte records (PSX used 0x2000), 744 events
43Menu text, including item names and rumor titles (message 4130 + rumor)
771Rumor bodies (message n = rumor n)

TEST.EVT records

Each 0x2800-byte record starts with a u32 offset to its text. The script runs from +4 up to that offset, and the text follows. A record whose text pointer isn't between 8 and 0x2800 is a placeholder.

  • Scripts use IC's classic opcode lengths. IC's exe has the table at file offset 0x67FF00, one byte per opcode.
  • Text is PSX-encoded and not compressed, messages separated by 0xFE, with 0x95 as the space (PSX uses 0xFA). A battle's events each carry the whole battle's text block, so message numbers are shared across them.

BOOT.BIN tables

BOOT.BIN is ELF offset + 0x8803FAC in PSP virtual addresses. Offsets below are file offsets in BOOT.BIN.

OffsetTableLayout
0x2EE184Event setup records712 × 0x18 bytes, same layout as IC's. IC's 512–599 are byte-identical.
0x2F2494Battle-event rulesu16 offset per rules key to a 0-terminated list of block offsets, all relative to 0x2F2494. A block is u16 op + u16 args.
0x31E698World-map triggersu16 offset per location (44, IC's town keys) to a 0-terminated list of block offsets, relative to 0x31E698. Blocks from 0x31E8E2: u16 op + args, conditions first, one action last.
0x31F85CRumor town masksu32 per rumor, the same table as IC's

Trigger ops and their argument counts: 01 var == (var, value), 02 var ≥, 03 var ≤, 04 in party (character), 0E gil ≥ (1), 10/11 date ≥ / ≤ (month, day), 19 play event (event, mode), 1A (8 args). Actions end a block: 00, 19, 1A, 1D, 20–24, 2A. Others: 1E (3 args), 1F/20/21/29 (2), 22/23/24/2A/2B (1).

How IC runs an event

Event setup records

The exe holds one 0x18-byte record per event (file offset 0x8EAE98, 713 used of 887 slots). Signature: 48 8D 1D ?? ?? ?? ?? 41 8B D4 BD 27 00 00 00. The LEA points at event 1's record, and an all-zero record ends the table. Look records up by their own id, not by position.

OffsetField
+0x00u16 event id
+0x02Map (byte)
+0x03Weather nibbles (high → var 0x30, low → var 0x23)
+0x04Time of day (1 = night) → var 0x24
+0x07u16 ENTD (the cast)
+0x0D/+0x0EPreloaded for the next event
+0x12/+0x13u16 next event
+0x14Flags: 0x80 back to the world map, then the next event; 0x81 play the next event now; 0x82 game over
+0x16Battle-event rules key (EnhancedBattleEvent); nonzero on stubs and battles

The setup function is RVA 0x2FB7C8, and var 0x27 holds the id of the event being played.

Stubs

Every vanilla world trigger starts a stub: an empty event (event000.e) with a rules key. The stub shows the confirm prompt or sortie screen. Its rules' first block, var 509 == 1 → play N+1, starts the real scene. The mod's first attempt triggered a scene directly, without a stub, and crashed on load, so every port uses the pattern.

EventId (nxd)

One row per event. The simplest approach is to copy the vanilla row that plays the same role.

Battle-event rules (EnhancedBattleEvent)

Triple-keyed: Key = rules key, Key2 = block, Key3 = step. Blocks are tried in order. The first whose conditions all hold plays its event, and the battle keeps checking them as it runs. WotL's ops map one to one onto IC's rows (checked on vanilla key 41).

Battles use scratch vars 0x7D–0x81 so each turn talk plays once (the talk event sets its var).

A rule that names a unit goes through the CharaControlId table (nxd 0xDA): Key = the id used in the rule, Unknown8 = the actual unit id. Vanilla covers 0–52, 100–103, 128–139, 256, 500–509 and 1000–1006. A WotL-only unit (Balthier 0xA2) needs a row such as 162 → 162, or battle setup dereferences null at RVA 0x2FC2E3.

World-map triggers (EnhancedWorldEvent)

Key = location (0–14 are the towns), Key2 = block, Key3 = step. Blocks are tried in Key2 order, and the first whose conditions all pass fires. Append new blocks after the location's highest Key2.

Set Unknown14 and Unknown18 to 47 as the vanilla rows do. The evaluator is at RVA 0x343AF8. It rebuilds WotL's u16 bytecode from each block and runs handlers from the table at 0x684E90. WotL's date ops 0x10/0x11 aren't in IC's rows, so compare the calendar vars instead: var 0x2E is the month, 0x2F the day.

Variables

The event variable function is 0x2EC298. Vars 0–0x7F are u32, 0x80–0x35F are single bits (stored from block +0x200) and 0x360–0x3FF are 4-bit. Other useful ones:

  • 0x2C gil; 0x2E/0x2F month and day.
  • 0x6E story progress (WotL's trigger windows use exact values of it); 0x6F chapter milestone (13 at chapter 4's start, 16 later).
  • 0x27 the current event.
  • 0x55 WotL's "next story event"; IC doesn't use it for hand-offs.

GetVar is 0x2332D8, SetVar 0x233368 and the script's variable-op dispatcher 0x242700.

Porting a WotL event

IC already has the setup records for 512–599 (map, cast, rules key, chaining) and the casts for 512–533. A port adds the rest:

  1. Scripts. Convert each event's script (next section) to script/enhanced/eventNNN.e. Stubs get a copy of vanilla event000.e.
  2. Text. Give every page a global text id and write the scene's scenario file (below).
  3. EventId rows copied by role (table above).
  4. Rules rows from WotL's rules table, same keys (146–164).
  5. A trigger from WotL's trigger table, unless the scene is started by another event's record.
  6. Cast support rows: CharaControlId for units the rules name, EntryNo for the ENTD, CharShape for every sprite set the cast uses.
  7. Pre-battle screen: a SortieConfirm row, or a continuous-battle row for a chain battle.
  8. Title, objective, speakers, and any missing sprite-sheet textures.

Text files

An event's lines live in nxd/text/scenario/scenario<key>.en.pzd, where key is the ScenarioId row whose EventIds list includes the event. That row's UnknownC is a ScionFiles key whose File is nxd/text/scenario/scenario%04d.pzd (the language is inserted). Text ids are global and unique: vanilla uses 300000–357600, and this mod uses 381590 and up, 100 per scene group.

Write the lines as YAML and convert with FF16Tools.CLI pzd-conv -i scenarioNNNN.en.yaml:

- Id: 382000
  Line: 'You''ve a fine eye for a pirate.'
  Speaker:
    Type: 24
    Value: 1162000
  VoiceSoundPath: ''
  ShowType: Normal
  ShortVoiceSoundPath: ''
  IsShortened: false

Speaker values are rows of Speaker-en (code → name plate), for example 1010103 Ramza, 1030100 Agrias, 1020101/1020102 Delita. New names get new rows: the mod adds Balthier 1162000, Luso 1163000, Assassin, Northern Sky Scout, Mysterious Voice, Delita's Voice, Aliste, Celebrant Bremondt, Ninja and Northern Sky Deserter. A line with no speaker row is allowed. A line can also override the name inline with <speaker="Name">.

Casts

  • ENTD ids ≥ 512 come from fftpack event_btlevt_bin_entrydata_add_ent.bin (entry = id − 512, 0x280 bytes). The loader (0x284098) allocates room for 80 entries, so ids 512–591 are addressable. IC's file already has WotL's casts 512–533. Units can be redefined without replacing the file through OverrideEntryData (Key = ENTD, Key2 = slot).
  • EntryNo (base row id) needs a row for every ENTD. The row picks formation or none: story battles with a formation use UnknownC [0, N, 0] (N rises through the story, 5,700–8,300 for these battles) and Unknown14 [130,145,130]. Scenes and preset-unit battles use []. A missing row crashed battle setup (0xFB6C8).
  • CharShape (base row id, keyed by sprite set) needs a row for every sprite set on screen. Vanilla stops at 0x9E. A missing row is a null read at 0x217172. For a humanoid sprite, copy row 0x83.
  • A unit can be player-controlled without a formation (Delita at Yardrow and Zeirchele): that is a flag in its ENTD entry, not EntryNo.

Pre-battle screen

A story-battle stub points at a SortieConfirm row (union 7:<row>), copied from a vanilla battle on the same map; MapId is the panel's map. The panel only shows if Unknown2C != 0. Every vanilla story battle has 0 and starts on arrival, as WotL did. Chain battles use ContinuousSortieConfirm instead (minimap).

Location titles

WotL scripts show titles with ShowMapTitle (0x91), which IC removed from every script; it only gives a silent black screen. IC's own opcode is E7 <u32 Caption id>. It takes a Caption row, not a PlaceName: Caption rows point at a PlaceName through UnionId '113:<PlaceName>', for example 1200 → 12000 "Zeltennia Castle Keep". Place E7 right before the scene's first Reveal (0x4D); at the very start of the script it shows nothing. New titles need new Caption rows (the mod adds 1310 → Lenalian Plateau, 1320 → Zeirchele Falls).

Battles take their title and save-file name from the Map row instead: Unknown8 = title PlaceName, UnknownC = region, Unknown10 = spot. The save entry is region + spot.

Objectives

DisplayConditions (0x78) takes 8 + a BattleObjective row. Rows 35–68 are WotL's and have no names in IC because WotL drew objectives as images. Name the ones you use in BattleObjective-en (for example 37 "Defeat Argath!", 40 "Protect Luso!").

Converting a WotL script

WotL scripts already use IC's classic opcode set. Enhanced-mode scripts differ in only three lengths, and IC's own opcodes occupy ranges WotL doesn't use:

OpcodeClassic / WotLEnhancedChange

51 ChangeDialog5751 box <u32 text id, FFFFFFFF = close> <2 bytes>

IC defines its own meanings for A6–AF, C2–CE and E7–EE. Stop if a WotL script uses one of those. Check every converted script by walking it with the enhanced length table to the EventEnd (0xDB); all 560 vanilla enhanced scripts parse that way.

Pages and boxes

  • One page per text id. WotL separates pages with blank lines inside one message. IC gives each page its own id and advances with E5 01 00 (wait) + 51 box <next id> 00 00. Join each page's own line breaks with spaces.
  • Keep pages to about 150 characters. IC's box shows three lines; 99% of IC's lines are 146 characters or less. Split longer pages at sentence ends.
  • The box style is the high nibble of the type byte and the box slot the low nibble. A style IC never uses (ReMixed's 6) indexes box slot −1 and crashes (0x136541).
  • Speech bubbles (1x) never page in IC. A multi-page bubble becomes the portrait box of the same slot (9x), paged as above and closed after its last wait with 51 box FFFFFFFF 00 00.
  • In-battle speech (0x70) with several pages becomes IC's 0xF0 box: E5 01, EB <this> <next> 00 00 per page, and EB <last> FFFFFFFF 00 00 after the last wait.
  • A reward or system line with no speaker: type 0x12 on unit 0xFD (no unit), then close box 2.

Other changes

  • Recruitment. WotL shows the join window (78 07 3C, E5 38 00) under a dark screen. Every IC recruitment (170, 213, 298, 374) shows it after the final fade instead: 3E …, E5 0C 00, F1 3C 00, 78 07 3C, E5 38 00. Move it the same way. The scenes contain the party check 0xA2.
  • Story hand-offs. WotL ends hand-off events with a write to var 0x55 (the next event) and CallFunction 06. IC never uses either, so drop both, and use the setup record's next event instead (story links). ADD accumulates, so "set 0x55 to 200, then add 195" means 395.
  • ShowMapTitle → E7 <Caption> before the first Reveal (above).
  • Maps IC lacks HD data for: rewrite ChangeMap (0x4C) targets and any WarpUnit (0x5F) / WalkTo (0x28) tiles off the stand-in map. The scene's first map is the setup record's +2, patched in memory.
  • Scenes only a chain ever reached may never set their own "seen" flag. When a port also triggers them from the map, append BE var + B0 var 1 before the EventEnd.
  • Vars that WotL's rumors use are renumbered when the rumor ids shift (rumors).

Event art and sprites

Event sprite sheets

Scripts load special pose sheets with LoadEVTCHR (0x58). In enhanced mode each sheet is drawn from a texture system/ffto/g2d/tex_NNNN.bin: raw 512 × 512, 4 bits per pixel. The exe maps sheet → texture number with a u32 table of 143 entries at file offset 0x7136B4 − 0x89 × 4. Two problems:

  • WotL-only sheets 0x89–0x8E (textures 1279–1284) ship in IC as copies of sheet 0x36, so poses draw as scrambled pieces. The mod ships real ones.
  • Vanilla sheets WotL drew extra frames on. IC's textures stop at row 442 of 512, and WotL put new poses below that (Ovelia's grass whistle on 0x1E, her prayer on 0x7C and others). The mod ships IC's own rows 0–441 with only rows 442–511 added, so vanilla scenes keep IC's art.

IC's own textures are in g2d.dat: a u32 index offset at +8, a u16 count at +12, then 16-byte entries (u32 offset, u24 size). An entry's data is zlib-compressed from +16 when its +4 is 2.

The replacement pixels are from Spikedrose's "FF Tactics Mobile Sprites" (used with permission). That set redraws whole sheets with the same layout and palette.

Props and shapes

Agrias's Birthday's gift box is a unit with sprite set 0xA9 (unit_psp/spr_dst_bchr_sword_m_spr.bin, a PSP prop sheet IC ships). It only needed a CharShape row. The sprite type table (file offset 0x672300, 4 bytes per sprite set: SHP, SEQ, flying, height) says which frame layout a sprite set uses; type 0 is humanoid.

Portraits

A portrait goes: portrait table (index → face id) → face map (face id → wldface number) → texture ui/ffto/common/face/texture/wldface_NNN_08_uitx.tex (+ its textureparts).

  • Balthier (0xA2) and Luso (0xA3) are hard-coded by sprite set to faces 0x6C/0x6D → wldface 163/164. They only need the textures.
  • Sprite sets 0x82 and above take portrait table[MonsterPortrait of their job]. The mod points table entries 165–168 at face ids 0x63, 0x6F, 0x6E and 0x64, and face ids 0x63/0x64 at wldface 165/168 (0x6E/0x6F already map to 167/166).
  • There are six identical portrait tables, one per screen. Signature: 00 00 00 00 01 00 02 00 03 00 78 00 79 00 04 00 7A 00 7B 00 7C 00 7D 00 05 00 06 00 7E; find all six. The face map comes from the LEA in 48 8D 0D ?? ?? ?? ?? 8B 04 81 C3 B8 C2 00 00 00.
  • Crash guard. For face ids ≥ 0x3F the portrait code reads a global "last monster job data" pointer without a null check. It crashes if no monster portrait has been drawn yet. The mod seeds it with Ramza's chapter 1 job entry. The global is the store in 48 89 0D ?? ?? ?? ?? 0F B6 49 2E 41 80 F8 5B.

The separate guide Custom Unit Portraits in FFT: The Ivalice Chronicles covers portraits in more depth.

Tavern rumors

Four WotL rumors gate quests: Rash of Thefts → A Call for Guards (Balthier), Disorder in the Order (the Deserters) and Lionel's New Liege Lord (Beowulf and Reis). IC dropped them.

  • Rows. Gossip-en is base-row-id. IC's 0–21 are WotL's 0–21 and IC's 22 is its own "At Battle's End", so WotL rumors 22–25 become IC 23–26. The unlock vars WotL's scripts set (0x2E7–0x2EA, "var 0x2D1 + id") shift by one to match, in every converted script.
  • Where they're listed. A u32 town mask per rumor (bit 0x4000 >> town) at RVA 0x7BE620, found by B8 00 40 00 00 4C 8D 05 ?? ?? ?? ?? 8B CE D3 E8 41 85 04 B8. IC's entries past its own rumors are 0. The mod writes WotL's masks: Rash 0x4140, Call 0x0020, Disorder 0x1100, Lionel 0x056A. Availability (0x36F53C) also needs the unlock var set.
  • What reading does (0x19D548). If Unknown4 (a quest counter) is nonzero and that counter is below Unknown8, the counter is raised to Unknown8 and the Unknown14/Unknown1C action pairs run. Type 102 sets base = value × 10, anything else does SetVar(type + base, value).
  • Counters. IC's scripts use counters 0–3. The array is 12 dwords, followed by a byte flag bank, so the mod uses counters 4–6. An earlier version used 12 and overwrote the flag bytes.
  • The picture. The rumor screen shows a town picture only when Unknown4 > 0 and Unknown8 > 0, from IconId (Icon row 21, base_%02d_uitx).
  • WotL's actions are embedded at the start of each rumor body in fftpack 771 as F5 type F6 value. Rash of Thefts sets 0x2FA and unlocks A Call for Guards, A Call for Guards sets 0x2FB, Disorder sets 0x2FC and Lionel's sets 0x2FD.

Putting scenes back into the story

Three WotL scenes had no world trigger because WotL played them in the middle of IC's own story chains. WotL chained them with var 0x55 + CallFunction 06, which IC dropped. IC chains through the setup record's next event instead, so the mod rewrites records in memory. Each patch names the record's expected old byte and is skipped with a warning if it differs.

Maps

A map has two halves in IC. The classic half (GNS, textures and terrain in fftpack) drives movement, heights and events. The HD half (bg/meshes/map_NNN_mesh.bin, bg/textures/NNN/, the RefinedBg* tables) is what enhanced mode draws. HD meshes stop at map 116, and WotL's maps 125–127 have no HD half.

Stand-ins

Bervenia's scene (536) used WotL's map 126. It plays on map 20 (Zeltennia Castle Keep), then map 2 (Lesalia Castle Postern) after its ChangeMap. Both maps were checked to hold every WotL position.

Copying map 127

WotL's map 127 (Limberry Castle Inner Court) is Fort Besselat – South Wall (map 66) under another name, and IC already knows it. Its per-map file lists (exe 0x685450 and 0x685050, one per mode) give map 127 exactly map 66's classic files. Only the HD half was missing. The copy:

  1. Copy bg/meshes/map_066_mesh.bin to map_127_mesh.bin and change the u32 map id at +8 from 66 to 127.
  2. Copy the folder bg/textures/066/ to bg/textures/127/. The loader builds bg/textures/%03d/%s.tga from the map id.
  3. Copy map 66's rows in RefinedBgAnim, RefinedBgMeshNode, RefinedBgMeshPolygon, RefinedBgMeshPolygonCond, RefinedBgSystemTexture and RefinedBgTexture to key 127.
  4. Give Map row 127 map 66's settings and its own names: title 11850 "Limberry Castle Inner Court", region 1050 "Limberry Castle", spot 33250 "Inner Court". Add the new PlaceName rows in all four languages; PlaceName is sparse-keyed.

Patching the Map row in memory instead (an earlier version) worked but froze loading while it searched memory for the row.

Battle surfaces

Maps IC only uses for cutscenes have no battle surface: no grid, and a cursor stuck at one height. The chapel ruins (map 45), where Ovelia's Yardrow battle is fought, needed one generated. That work has its own guide: IC Battle Grid Guide.

The multi-stage battle minimap

IC shows a minimap before each battle of a chain (Limberry, Lionel, Orbonne and so on): the path, a marker per battle, and the party walking to the next one. It is data in two places.

A chain stub's EventId union is '289:<row>'. The row is "the confirm before battle N". Its list fields hold keys of ContinuousBattleTimeline, which names UI timelines: 1–9 MapA…MapH, 10–13 PointStart…Point03, 18–22 PositionStart…Position04, 25–28 Move01…04, 33–36 StayStart…Stay03, 39–42 Point01…04 as nodes.

The layout file

ui/ffto/battle/ffto_battle_continuous_map.uib holds 30 components. MapA…MapH are 900 × 540 layers over one 362 × 222 panel of the art sheet ui_battle_continuous_map_dotart_uitx (3 × 3 panels, all used). MapAll shows them and selects the panel. A component's stage count is fixed by its nodes and timelines; Limberry had 3 and MapH 4.

The format is FF16's UIBinary. Every offset is relative to the start of the structure that holds it, not to the field.

StructureFields

TOC+0 asset list, +4 component table, +8 count

Layout rules, read from IC's maps

  • A point's node origin is its marker's top-left; the marker's centre is origin + (30, 15).
  • A line starts at the centre of the point it leaves. Its rotation is atan2(dy, dx) to the next centre, its y-scale is −1 when it heads left, and its width is the distance.
  • The unit stands at about point origin + (0, −91).
  • HomePosition places the points and lines. Point N blinks the next marker and line, Move N walks the unit (a 5002 key at frame 0 and one at frame 120), and Position N and Stay N put it at stage N. There is no Point timeline for the last stage.

Giving a map another stage

  1. Copy a component that has enough stages (MapH) to the end of the file. Re-aim every offset that points outside the copied block (the shared string pool, asset data) by the distance it moved. Offsets inside the block move with it.
  2. Point the target component's record (+0xC, +0x10, +0x18 and the counts) at the copy. Its name and the MapAll reference stay as they are.
  3. Rewrite the copy's coordinates: node origins, line origin/rotation/scale/width, the HomePosition 5002 keys (matched by target name), and the unit's 5002 keys in every Point, Move, Position and Stay timeline.
  4. Change or add the ContinuousSortieConfirm rows and point the stubs' EventId unions at them.

A whole new component would also need the component table moved (it is a fixed 30-entry array, but only the TOC points at it), a MapAll reference node and timeline, and a ContinuousBattleTimeline name row. Nobody has checked whether the exe accepts map keys above 9.

WotL's 40 items

IC's item code is WotL's own: the same range table, data-type tables and getters. Its secondary tables only cover IC's five extra items (0x100–0x104), and its arrays and bounds are sized for 0x105 items. The mod keeps WotL's ids, since IC's code still special-cases them (the Onion gear is reserved for jobs 0xA1/0xA4 in the can-equip check). The exception is the five Fell Swords, whose ids IC took; they move to 0x116–0x11A. The full site list is in research/ITEM_EXPANSION.md.

Where the data comes from

In WotL's BOOT.BIN (virtual addresses): common records 0x8A5ADAC (12 bytes), weapons 0x8A5B07C (8), shields 0x8A5B17C (2), armor 0x8A5B184 (2), accessories 0x8A5B1A4 (2), equipment bonus rows 0x50–0x64 at 0x8A5B1B8 (0x19 bytes; IC's rows have a 26th byte, 0), and sprite pairs 0x8A5B3C8. Bonus rows move up by 5 (IC's own items use 0x50–0x54). Record byte 4 (the index in the item's vanilla sub-table) takes a similar vanilla item's value.

What has to change in the exe

  1. Hook the getters. RVAs 0x2B8BCC–0x2B8EF0 are the only code that reads the item tables: the range index 0x2B8BCC (hard-codes ≤ 0xFD or 0x100–0x104), common record 0x2B8C44, sub-getters 0x2B8C74/CD4/D3C/DA0/E04, sprite pair 0x2B8E60 and is-valid 0x2B8EBC. Answer ids ≥ 0x105 from your own tables and let everything below run the game's code.
  2. Move the per-item arrays to a page allocated near the exe, and re-point all 63 instructions that address them. The arrays are the bag counts (0x11A7C00), the owned mirror (0x3C52740), the bonus table (0x80FEA0, 0x55 rows × 0x1A) and the equip picker's all-items chart (0x1874726).
  3. Move the nine menu order charts by rewriting the 14 pointer slots their readers use.
  4. Widen the bounds that must see new ids: bag access, menu lists, chart walks, the five cmp …, 0x55 bonus-row checks, and the 16 "right hand ≥ 0x105" hand-slot checks. Leave alone, on purpose, the bounds of fixed buffers indexed by id (auto-sell, the 100-items check, the inventory reset, the "new in stock" array) and the steal/break code. There a new id reads as "no item", which is safe.
  5. Save the new counts without changing the save format. The event variable block (0x400 bytes) is saved whole by the serializer 0x218F78, load 0x21B0E8, and battle suspend/resume. No variable id reaches past +0x2FC, so the mod keeps a tag ("WC" 1 0) and one count per new id there. Mid-battle saves are covered, and a save loads without the mod; the new items then vanish.
  6. Keep the charts' vanilla save fields valid by projecting them back with vanilla ids only, both ways, on a short timer and when the serializer runs.

Arm everything or nothing: check every byte first, and if any site differs, leave the expansion off.

Data rows

  • Item-en/fr/de/ja are base-row-id. Ship every row 261–315, blank ones included. A lone row 312 sat at position 261, and the item showed no name, icon or description.
  • Each item needs a UiItemCategoryId and a SortOrder that is unique within its category. The Fell Swords get a new UIItemCategory row 35.
  • Icons are one texture per item id: ui/ffto/icon/equip_item/texture/ei_NNN_uitx.tex (100 × 100) and equip_item_s/…/ei_s_NNN_uitx.tex (48 × 48, BC7), each with a textureparts/*.utexpt giving its path.
  • Effect text uses IC's wording. The weapon effect table (ItemOptionsData) starts at RVA 0x80FBA0.

Balthier's gear

WotL doesn't put Ras Algethi and the Mirage Vest in his ENTD; ENTD item fields are one byte. The unit setup loop (IC 0x27176B) checks unit byte 0 == 0xA2 and var 0x27 == 518, then copies the 7-word table at 0x714460 (0, 0x12F, 0, 0x107, 0, 0, 0) over his equipment. IC still ships that code, so once the items exist he joins wearing them.

Only three items can be obtained in play: the Tynar Rouge (Agrias's Birthday) and Ras Algethi and the Mirage Vest (Balthier). WotL's other items came from its multiplayer modes. Shops stop at id 255, ENTD items are one byte, and steal/break isn't widened.

Agrias's Birthday reward

WotL's scene 579 ends by setting var 0x2F9, then 0xB6. The mod hooks the variable-op dispatcher at its call from the event interpreter. An identical copy of the dispatcher exists at 0x2EC038, so hook the call site, not the function. On ADD 0x2F9, 1 the hook gives one Tynar Rouge and multiplies Agrias's raw HP and MP (roster slot +0x20 and +0x23, 3 bytes each) by 1.1. It skips the reward if 0xB6 (seen) is already set, so a replay grants nothing.

The roster is 54 slots of 0x258 bytes, and the item counts sit 0x110 bytes before it. If the item expansion isn't armed, the reward falls back to a Septième Sens.
